# Security Policy

## Supported surface
Security fixes target the current default branch unless a maintained release is explicitly documented.

## Reporting a vulnerability
Do not publish exploit details, credentials, private data, or proof-of-concept material in a public issue. If GitHub shows a **Report a vulnerability** control, use it. Otherwise open a public issue titled `Security contact requested` with no sensitive details and request a private reporting path.

For an exposed credential, revoke or rotate it before discussing repository cleanup.

## Scope
Include the affected ref, boundary, and safely shareable impact.
